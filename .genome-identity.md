# arsenale

- **Scopo**: Archivio di prompt e agenti per "Project Reconstruction Engine" — sistema che ricostruisce le specifiche complete di un progetto software a partire dal transcript di una conversazione, preservando ogni decisione tecnica.
- **Stack**: Nessun framework — collezione di prompt testuali (TXT/MD) + directory di agenti/utilities (Python/JS misto); pensato come asset per agenti AI.
- **Entry point**: `ingress.txt` (prompt principale: Ultra Project Reconstruction Engine v7), `prompts/ingress_god_mode.txt` + `ingress_token_saver.txt`, `core/` (agents/ automation/ general/ projects/ utilities/), `CHRONOS_SCREENS.md`.
- **Comandi**: Nessuno (non e' un'app eseguibile; i prompt vanno forniti a un LLM/agent; `core/` contiene script e utilities da invocare dai singoli agenti).
- **Maturita'**: experimental (archivio di prompt/agenti; niente test, niente build; README e' solo lo stub di audit).
- **Gotcha**:
  - `ingress.txt` e' un prompt lungo ~165 righe con regole di paginazione esplicite ("Never summarize, Never truncate") — passarlo intero al modello, non troncarlo.
  - `core/` ha sottodirectory (agents, automation, general, projects, utilities) ma il loro contenuto va ispezionato per capire cosa sia pronto vs bozza.
  - Un file in `core/` contiene un nome con emoji "🧠" — il sistema globale vieta emoji nel codice, va rinominato/normalizzato se si tocca il file.
- **Deploy**: N/A (archivio di asset/prompt; nessun deploy).
- **Segreti**: `ingress_token_saver.txt` (presumibilmente gestisce token/credenziali — verificare il contenuto prima di committare per leak).
- **Dipendenze esterne**: Nessuna diretta; pensato per essere consumato da un LLM esterno (modello AI) o da agenti nei progetti consumers.
